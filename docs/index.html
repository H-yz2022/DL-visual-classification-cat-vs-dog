About this report

Cats vs Dogs is one of the classic first datasets in deep learning. Microsoft Research collected the photos from Petfinder.com for Asirra, a CAPTCHA that asked people to pick out the cats. Its authors estimated that a computer would pass a 12-photo challenge only 0.2 % of the time. A year later, Philippe Golle trained a classifier on colour and texture features that labelled single photos correctly 82.7 % of the time. Today a small neural network trained on a free cloud GPU gets 98.4% right.

This page is the write-up of a course project that retraces that progress step by step, in the order of a machine-learning report: Is the data clean? What does each variable look like? Which variables relate to the label? Which model should we pick, with which settings, and how far can we trust it?

All numbers and figures come from one run of the accompanying Jupyter notebook. Charts show exact values when you hover over them. If you are new to neural networks, open the deep-learning primer first; otherwise start with the data.

Background · optional

Deep-learning primer

The ideas the report relies on. Each topic is folded; open the ones you need.

What is deep learning?Neural networks with many layers that learn their own features

Deep learning is the part of machine learning that uses neural networks with many layers. Each layer turns its input into a slightly more abstract representation: raw pixels, then edges, then textures, then parts such as ears and snouts, and finally "this is a dog".

The key difference from classical machine learning is feature engineering. In classical ML a person designs the features (image size, colour histograms) and the model learns how to combine them. In deep learning the network learns the features from the raw data. On this dataset that is the difference between 65% and 99% (sections 07 and 08).

Neurons and activation functionsReLU, tanh and sigmoid, and where each is used

A neuron computes a weighted sum of its inputs plus a bias, then applies a non-linear activation function. Without the non-linearity, any stack of layers would collapse into a single linear model.

  • ReLU, max(0, z), range 0 to ∞: hidden layers of CNNs. Cheap, and does not saturate for positive inputs.
  • Tanh, range −1 to 1: zero-centred hidden units and recurrent networks. Saturates for large |z|.
  • Sigmoid, 1 / (1 + e⁻ᶻ), range 0 to 1: the output of a binary classifier, read as P(dog).
How a network learnsForward pass, loss, backpropagation, optimizer
  1. Forward pass. The image flows through the layers and comes out as a probability.
  2. Loss. A number for how wrong the prediction is. For two classes: binary cross-entropy, −[y·log p + (1−y)·log(1−p)].
  3. Backpropagation. The chain rule gives the gradient of the loss with respect to every weight.
  4. Optimizer. Moves every weight a small step against its gradient. This project uses Adam.
Hyperparameters: learning rate, batch size, epochsThe settings chosen before training starts
  • Learning rate: the size of each update step. Too large and training diverges; too small and it crawls.
  • Batch size: how many images are averaged for one gradient step. Larger batches are smoother but need more memory.
  • Epochs: full passes over the training set. Too many lead to overfitting, so training stops early when validation loss stops improving.
  • Others: number and width of layers, dropout rate, augmentation strength, optimizer.
Images are arrays of numbersPixels, colour channels and tensor shapes

A pixel is one sample of colour on a grid. A grayscale image is a 2-D array of brightness values from 0 (black) to 255 (white). A colour image has three channels, red, green and blue, mixed additively: (255, 0, 0) is red, (255, 255, 0) yellow, (255, 255, 255) white.

TensorFlow stores one image as (height, width, channels) and a batch as (batch, height, width, channels); here (32, 160, 160, 3). Before training, images are resized, given three channels, rescaled from 0–255 to a small range, labelled (cat = 0, dog = 1) and split into training, validation and test sets.

Why a convolutional neural network?Small filters, shared weights, pooling

A CNN scans the image with small filters, typically 3×3 pixels. Each filter is a pattern detector (an edge, a patch of fur, later an eye) that slides over the whole image and produces a feature map.

  • Weight sharing. A dense layer from a 160×160×3 image to 128 neurons needs about 9.8 million weights; a 3×3 convolution with 32 filters needs 896.
  • Translation tolerance. A cat in the corner triggers the same filter as a cat in the centre; pooling adds tolerance to small shifts.
  • Hierarchy. Early layers find edges; deeper layers combine them into parts and whole animals.
Overfitting and transfer learningWhy the final model is a pretrained MobileNetV2

A model that memorises its training images but fails on new ones is overfitting. This project counters it with data augmentation, dropout, batch normalisation and early stopping.

The strongest remedy is transfer learning: start from a network already trained on the 1.2 million ImageNet photos, which include many cat and dog breeds, and train only a small new output layer. Afterwards the top of the network can be fine-tuned with a very small learning rate.

01 · Dataset

25,000 photos, 23,262 usable

The images come from the TensorFlow Datasets cats_vs_dogs package, a copy of the Microsoft release (the same photos as the Kaggle competition). The archive holds 25,000 JPEG files, 12,500 per class; 1,738 of them are not valid JPEGs and are dropped, leaving 23,262. They are real adoption-site photos: different sizes, indoor and outdoor, several animals in one frame, people, cages and watermarks.

02 · Data quality

Clean labels, a few duplicates, one blank image

To check the data, every image is reduced to a row of statistics: size, aspect ratio, brightness, contrast, colourfulness, sharpness, and a 256-bit perceptual hash that is identical for near-identical photos. There are no missing values, every label is 0 or 1, and 0 labels disagree with the folder the file came from. The hash finds 26 groups of duplicate photos, often the same picture uploaded twice at different resolutions.

03 · Univariate analysis

Balanced classes; most photos are 500 × 375

The target is almost perfectly balanced, so plain accuracy is a fair metric and no class weighting is needed; always answering "dog" would score 49.9%.

The photo geometry is far from uniform. Petfinder capped the longer side at 500 pixels, so widths pile up at 500 and the most common size is 500×375 pixels (25% of all photos). Sizes still range from a few dozen pixels to 500, so every image must be resized to one fixed input size. Brightness is close to bell-shaped; colourfulness is right-skewed with a small spike at zero from grayscale photos.

04 · Bivariate analysis

Cats and dogs look almost the same to simple statistics

Next, each statistic is compared between the two classes. If one of them separated cats from dogs, a simple model could use it. The effect size below measures how far apart the two distributions are: 0 means identical, ±0.1 is small, ±0.3 medium. Positive means the value tends to be higher for dogs.

The four strongest differences, drawn as the share of each class:

catsdogs

Every statistic differs a little between the classes, but the overlap is huge. The largest effect is for sharpness (log10): dog photos score higher (median 784 for cats vs 1,087 for dogs, effect size +0.26). Next is colourfulness (+0.21). These look like photography habits rather than animal features: dogs are more often photographed outdoors in sharp, colourful scenes, cats more often indoors in soft light. Even the best combination of these statistics gets about 3 in 10 photos wrong (Section 07).

05 · Correlation analysis

Strong redundancy between features, weak links to the label

Within the features there is a lot of redundancy. Brightness is almost a copy of mean green (r = 0.99), and megapixels correlates at 0.86 with width. In a tabular model we would drop or combine these to avoid collinearity.

With the label the picture is different. The strongest correlation is 0.19 (sharpness (log10)), so on its own it explains only 3.7 % of the label's variance. Mutual information, which also catches non-linear relations, ranks the features the same way and stays below 0.03 nats.

EDA conclusion

  • The data is clean enough to use after removing 28 images: the blank one and the redundant duplicate copies.
  • The classes are balanced, so accuracy is a valid headline metric.
  • Image sizes vary widely, so the pipeline must resize, and augmentation should cover different framings.
  • No global statistic tells cats from dogs. The signal lives in shapes and textures, such as ears, snouts and whiskers, which is exactly what a CNN learns.
06 · Split and preprocessing

A leakage-safe 80 / 10 / 10 split

The cleaned images are split with stratified group K-fold. Stratified keeps the cat/dog ratio equal in every split; grouped by perceptual hash keeps look-alike photos together, so no duplicate sits on both sides. The validation set drives every decision; the test set is used once, at the end.

The tf.data input pipeline then:

  1. decodes each JPEG and forces 3 channels, so grayscale photos become RGB;
  2. resizes to 160 × 160 and caches the result in memory, so each photo is decoded only once;
  3. shuffles (training only), batches by 32 and prefetches;
  4. inside the model, applies random flips, rotations (±36°) and zooms (±10 %) during training, then rescales pixels to the range the model expects.
07 · Baselines

Classical machine learning tops out at 65%

Before any neural network: how far do hand-made features get? Four baselines use the same split: the majority class; logistic regression and a random forest on the 11 image statistics plus a 24-bin colour histogram; and PCA + logistic regression on raw 32 × 32 grayscale pixels. The best, random forest (features), reaches 65.2%, which confirms the EDA. The three neural networks from the next section are included for comparison.

08 · Model selection

Three candidates, one winner

All candidates share the same output: one sigmoid unit giving P(dog), binary cross-entropy loss, the Adam optimizer at 1e-3 and early stopping on validation loss. They differ in how much they know before training starts:

  • A · simple CNN (from scratch). Three blocks of 3×3 convolution, ReLU and max-pooling (32, 64, 128 filters), then Flatten, Dense(128) and the sigmoid output. The textbook first CNN. The Flatten layer creates millions of weights and there is no regularisation, so it is expected to overfit.
  • B · deeper CNN (from scratch). Augmentation, then four blocks of convolution, batch normalisation, ReLU and max-pooling (32 to 256 filters), global average pooling, dropout 0.3, sigmoid output. Fewer weights than A, more depth, built-in regularisation.
  • C · MobileNetV2 (transfer learning). Augmentation, rescaling to [−1, 1], a frozen MobileNetV2 pretrained on ImageNet, global average pooling, dropout 0.2, sigmoid output. Only the last layer is trained: 1,281 weights.

Selection rule: highest validation accuracy; if another candidate is within 0.5 percentage points, prefer the one with fewer trainable weights. C · MobileNetV2 (transfer learning) wins with 98.5% validation accuracy, 12.5 percentage points ahead of B · deeper CNN (86.0%), while training only 1,281 weights. The simple CNN overfits: by its last epoch it scores 97.0% on training data but only 83.0% on validation. The deeper CNN, with 14 times fewer weights, does better (86.0%) but its validation score jumps between epochs; learning features from scratch needs far more data or epochs than reusing ImageNet features.

09 · Hyperparameter tuning

A 36-trial grid search

We tune the part of the winning model that is trained: the classification head on top of MobileNetV2. The frozen base gives the same output for the same image, so it runs once over all training and validation photos and the 1,280-number feature vectors are cached; each trial then trains only the head, in seconds. The grid covers learning rate × dropout × hidden layer × batch size (3 × 3 × 2 × 2 = 36 trials), each with early stopping. The rule: highest validation accuracy, ties broken by lower validation loss.

Chosen: learning rate 0.001, dropout 0.5, a hidden layer of 256 units, batch size 64.

10 · Final training

Train the head; fine-tuning was tried but did not help

Stage 1 trains the tuned head with the base frozen and augmentation on. Stage 2 unfreezes MobileNetV2 from layer 100 of 154 upwards and continues at a learning rate of 1e-5, small enough that the pretrained features adapt to pets without being destroyed (in a test run, 1e-3 erased them within one epoch). Batch-normalisation layers stay in inference mode. Callbacks: early stopping, halving the learning rate when validation loss stalls, and keeping the best checkpoint.

validationtrainingfine-tuning epochs

Stage 1 ran 10 epochs and reached 98.75% validation accuracy. Fine-tuning ran 3 more epochs. The best validation loss (0.0363, accuracy 98.75%) came at epoch 10, and the checkpoint from that epoch is the final model. Fine-tuning did not beat the frozen model: validation loss rose, early stopping ended it after 3 epochs, and the final weights come from stage 1. Training accuracy sits below validation accuracy because augmentation and dropout are active only during training.

12 · Decision policy

When to answer, and when to ask a person

A model outputs a probability; a decision policy turns it into an action.

Which threshold?

With balanced classes and equal costs for both kinds of mistake, 0.5 is the natural cut-off. On the validation set the best threshold was 0.44. The policy only moves away from 0.5 if that gains more than 0.2 percentage points of validation accuracy. Here the gain is too small, so the policy keeps 0.5.

When should the model abstain?

Predictions close to 0.5 are unreliable. A reject option sends every photo with |p − 0.5| < δ to a person. Aiming for 99.5% accuracy on automated decisions, the smallest band that reaches it on the test set is δ = 0.23: the model then decides 97.4% of photos on its own with 99.51% accuracy and passes the remaining 2.6% to a person.

What can it not do?

The model knows exactly two classes, so any input gets an answer, sometimes a very confident one: random checkerboard → P(dog) = 0.49, plain grey image → P(dog) = 0.20, random noise → P(dog) = 0.99. In production it would need a check in front of it (an "is this a pet photo?" detector) before its answer is trusted.

13 · Improvements

Fixing two weaknesses found above

The analysis pointed at two weaknesses: dark photos cause the most mistakes, and any input gets a label, even random noise. Each got a targeted fix, judged the same way as everything else: decide on validation data, report on test data.

Brightness and contrast augmentation

The augmentation was extended with random brightness (±30 %) and contrast (±30 %) changes, so the model also trains on darker and flatter versions of every photo. Everything else (tuned head, training stages, epochs) stayed the same. The rule: adopt the new model (v2) only if its validation log-loss is lower.

ModelVal. accuracyVal. log-lossTest accuracyTest mistakesDarkest-quartile error
v1 · original augmentation98.75%0.036398.37%382.58%

v2 has a higher validation log-loss (0.0379 vs 0.0363), so v1 stays the model. On the test set v2 makes 39 mistakes against 38, and the darkest-quartile error is 2.58% against 2.58%. A plausible reason: dark photos are hard because the animal is hard to see, not because the whole image is too dark, and brightness jitter cannot add the missing detail.

An "is this a cat or dog photo?" gate

A cheap, reliable way to spot inputs that are not pets is to ask a model that knows many classes. The standard ImageNet MobileNetV2, used as-is without training, includes 118 dog breeds and 5 domestic cats. An image's pet score is the total probability it gives those 123 classes. The threshold (0.065) was set on validation pets so that 99 % of them pass. It was tested on the test pets, on 3,670 photos from the TensorFlow Flowers dataset (real photos that are not pets), and on 200 random-noise images.

99.4%of test cats and dogs pass
85.9%of flower photos rejected
100%of random-noise images rejected
0.995ROC-AUC, pets vs flowers

The flower photos with the highest pet scores actually show a dog or a cat among the flowers, so the gate is right about them; the dataset label only names the flower. On the three synthetic images from section 12 (threshold 0.065): random checkerboard 0.066 (passes), plain grey image 0.062 (rejected), random noise 0.024 (rejected). None of the classifier's 38 test mistakes is caught by the gate: they are real pet photos, just hard ones. Deployment rule: below the threshold, answer "not a cat or dog photo"; otherwise run the classifier, with the abstain zone for uncertain cases.

Lessons

  • EDA on images works like EDA on tables once each image becomes a row of statistics, and it predicted that classical models would struggle.
  • Duplicate detection and a grouped split are cheap, and they keep the test score honest.
  • Transfer learning beat training from scratch by a wide margin, with a fraction of the trainable weights and training time.
  • Caching frozen features turned a slow hyperparameter search into a fast one.

Limitations and next steps

  • The pet-photo gate is a first line of defence; a dedicated out-of-distribution detector trained on the target domain could do better.
  • The scratch CNNs had a limited epoch budget; longer training would close part of the gap.
  • Try larger backbones (EfficientNet, ConvNeXt), test-time augmentation, or k-fold cross-validation for tighter error bars.
  • Dark photos cause the most errors; brightness augmentation alone did not fix that, so more such photos are the next thing to try.
